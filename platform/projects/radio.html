라디오 방송 구간 탐색 플랫폼

기존 다시듣기는 한 시간짜리 방송을 처음부터 재생해야 원하는 대목에 닿았습니다.
방송을 의미 단위로 나누고 태그를 붙여 구간 단위로 찾아 들을 수 있게 만들었습니다.

기간
2025.03 – 2025.08
내가 맡은 일
개인 프로젝트. 음성 인식과 의미 단위 분할 파이프라인 설계 및 구현, 프론트엔드와 백엔드 개발
사용 기술
React / Flask / MongoDB / Whisper / GPT-4o-mini

통째로 들어야 하는 구조

라디오 다시듣기는 한 시간 분량을 처음부터 끝까지 재생하는 방식이었습니다. 원하는 곡이나 사연이 어디쯤 있는지 알 수 없으니 듣고 싶은 대목 하나 때문에 방송 전체를 넘겨 가며 찾아야 했습니다.

연구실에서 학부연구생으로 진행한 개인 프로젝트입니다. 음성 파일 하나를 사용자가 탐색할 수 있는 단위로 바꾸는 것이 목표였습니다.

음성에서 구간으로

음성 수집방송 원본 확보
텍스트 변환Whisper로 전사
의미 단위 분할내용 단위로 나누고 태깅
탐색과 재생날짜·키워드·구간 재생

Whisper로 음성을 텍스트로 옮기고 그 결과를 LLM이 내용 단위로 나눠 태그를 붙이도록 구성했습니다. 분할 결과는 MongoDB에 저장하고 Flask로 API를 만들어 React 화면에서 날짜와 키워드로 찾아 해당 구간부터 재생할 수 있게 했습니다.

구간에 나온 음악과 영화는 외부 API로 메타데이터를 채웠습니다. 사용자가 무엇이 나왔는지 따로 검색하지 않아도 되게 하려는 의도였습니다.

나눈 결과를 그대로 쓰지 않았습니다

파일을 통째로 넣으니 처리 시간이 문제였습니다

한 시간짜리 음성을 한 번에 변환하려니 처리 시간이 길어졌습니다. 파일을 나눠 배치로 돌리는 방식으로 바꿔 전체 소요를 줄였습니다.

경계에서 맥락이 끊겼습니다

내용을 나눌 때 앞뒤가 잘려 문맥이 사라지는 구간이 생겼습니다. 한 번에 넣는 분량을 조정하고 구간을 조금씩 겹치게 해서 경계에서 내용이 이어지도록 했습니다.

외부 API 호출을 줄였습니다

메타데이터를 매번 조회하면 호출 제한에 걸렸습니다. 한 번 받은 결과를 저장해 두고 재사용하도록 바꿨습니다.

결과

구간 단위 탐색

방송 전체를 재생하지 않고 날짜와 키워드로 원하는 구간을 찾아 그 지점부터 들을 수 있게 됐습니다.

보유한 방송 데이터에 대한 결과입니다. 분할 품질은 방송 내용과 녹음 상태에 따라 달라집니다.

남은 기준

원본이 길다고 해서 사용자가 긴 단위로 쓰는 것은 아니었습니다. 데이터를 어떤 단위로 쪼개 놓느냐가 사용자가 무엇을 할 수 있는지를 정했습니다.

모델을 붙이는 일보다 그 출력을 어떤 단위로 저장하고 어떻게 찾게 할지 정하는 일에 시간이 더 들었습니다. 데이터를 다룰 때 저장 단위부터 정하고 시작하겠습니다.
