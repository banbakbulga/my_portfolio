사내 기술문서 검색 데이터 자동화

문서가 변환됐다는 것만으로 검색에 쓸 수 있는 것은 아니었습니다. 연구원이 답변 근거를 확인할 수 있도록 표와 제목 구조를 보존하는 데 집중했습니다.

기간
2025.09 – 2025.12
내가 맡은 일
문서 정제 담당. 변환 도구 비교와 청킹 기준 수립 및 색인 자동화 수행
사용 기술
Python / MarkItDown / 한컴 변환 도구 / OpenSearch

업무의 출발점

사내 기술문서 약 2,000건을 AI 챗봇의 검색 데이터로 가공하는 업무를 맡았습니다. PDF와 PPT부터 HWP까지 문서 형식이 다양해 수작업 변환과 정제에 약 두 달이 예상됐습니다.

처리 시간뿐 아니라 변환 품질도 문제였습니다. 표가 깨지면 항목과 수치의 관계가 사라져 문장을 검색하더라도 연구원이 잘못된 정보를 얻을 수 있었습니다.

자동화한 범위

문서 변환형식별 변환 도구 선택
정제반복 영역 제거와 구조 보존
청킹과 임베딩제목과 본문 기준으로 분할
검색 색인OpenSearch에 적재

처음 맡은 문서 정제에서 작업 범위를 넓혀 임베딩 생성과 검색 색인까지 Python으로 연결했습니다. 반복 실행이 필요한 작업을 하나의 흐름으로 묶고 연구원의 피드백을 정제 기준에 반영했습니다.

업무 구조를 설명하기 위한 개념도입니다. 사내 원문과 실제 연구 데이터는 포함하지 않았습니다.

기술적 판단

처리 속도보다 문서 구조를 먼저 비교했습니다

같은 문서를 MarkItDown과 한컴 변환 도구로 각각 처리해 표와 제목 구조가 얼마나 유지되는지 살폈습니다. 한 도구로 모든 형식을 처리하지 않고 문서 형식별로 적합한 도구를 선정했습니다.

Markdown 변환 결과에서는 반복되는 머리말과 꼬리말을 제거하고 제목 계층을 보존하도록 정제 기준을 코드에 반영했습니다.

사용자 의견을 문서 분할 기준으로 바꿨습니다

연구원에게서 답변이 문서의 어느 대목을 근거로 삼았는지 알기 어렵다는 의견을 받았습니다. 제목과 본문 구조를 기준으로 청킹 경계를 정하고 변환 결과를 함께 확인하며 보정했습니다. 단순히 일정한 길이로 자르는 것보다 내용의 맥락을 유지하는 것이 우선이었습니다.

처리 결과

2개월 예상 → 1개월 이내

약 2,000건의 문서 처리를 예상 기간보다 앞당겨 마쳤습니다.

연구원들에게서 실무에 쓸 만하고 오류도 거의 없다는 평가를 받았습니다. 이 평가는 실제 사용자에게 받은 정성적 피드백이며 별도로 측정한 검색 정확도 수치는 아닙니다.

업무에 남은 기준

데이터 전처리의 완료 기준을 파일 생성 여부에 두지 않게 됐습니다. 사용자가 답변을 이해하고 근거를 확인할 수 있는지 살피며 도구와 정제 기준을 선택합니다. AI 기능을 업무에 적용하려면 사용자 의견이 코드의 어떤 기준으로 이어지는지까지 구체화해야 한다는 것을 배웠습니다.
