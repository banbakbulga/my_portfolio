AI 경기 리뷰 지식베이스

검색에 성공한 것과 질문에 제대로 답한 것은 달랐습니다. 의도 분류부터 근거 전달과 채점까지 나눠 살피며 AI 경기 리뷰용 지식베이스를 개선했습니다.

기간
2026.06 – 2026.09
내가 맡은 일
데이터 수집과 검색 구조 설계부터 평가 체계 구축까지 주도
사용 기술
Python / 구조화 검색 / LLM 질의 라우팅 / 회귀 평가

어려웠던 점

게임 규칙과 통계는 갱신 주기가 다릅니다. 같은 챔피언에 관한 자료라도 패치 기준이 다르면 조언이 어긋날 수 있어 출처와 버전을 구분한 지식베이스가 필요했습니다.

자료를 모으고 검색 기능을 구현한 뒤에도 문제가 남았습니다. 검색 회귀 테스트는 통과했지만 실제 질문에서는 필요한 조건을 빠뜨리거나 자료가 있는데도 답할 수 없다는 응답이 나왔습니다. 어느 단계에서 정보가 누락되는지 밝히는 일이 가장 어려웠습니다.

구현한 구조

원천 자료에서 바로 답변을 만들기보다 검증한 문서와 구조화된 색인을 미리 준비했습니다. 질문을 해석하는 단계와 문서를 검색하는 단계를 분리해 같은 입력의 검색 결과를 다시 확인할 수 있도록 했습니다.

출처별 수집규칙과 통계의 버전 기록
문서 검증검증한 위키와 색인 준비
질의와 검색의도 분류 후 근거 발췌
답변과 평가질문과 원문을 함께 대조

구현 흐름을 설명하기 위해 재구성한 개념도입니다. 이 프로젝트의 검색은 임베딩 유사도 대신 구조화된 색인과 규칙을 사용합니다.

LLM이 질문의 의도를 구조화하면 검색기가 해당 문서와 필요한 구절을 찾아 전달합니다. 검색기 자체는 LLM이나 외부 네트워크를 호출하지 않도록 구성했고 의도 분류가 실패하는 경우에는 키워드 기반 경로를 두었습니다.

판단과 수정

자료를 더 넣기 전에 전달 경로부터 확인했습니다

의도 분류 결과와 검색된 발췌문 그리고 최종 답변을 기록해 비교했습니다. 챔피언 약칭을 인식하지 못한 경우와 문서를 찾고도 필요한 조건을 전달하지 못한 경우를 구분했습니다.

실패 사례수정한 지점
‘킨드’를 챔피언으로 인식하지 못함약칭을 별칭 색인에 연결
스킬 발동 순서를 빌드 순서로 해석질문 의도 분기 수정
일반 칼바람 질문을 증강 질문으로 처리스킬과 증강의 검색 경로 분리

이 사례들은 이미 보유한 사실을 찾아 전달하는 과정의 문제였습니다. 해당 개선 단계에서는 위키 사실 본문을 다시 쓰지 않고 검색과 전달 경로를 수정했습니다.

자동 채점 결과도 원문과 대조했습니다

브라움 패시브에 대한 답변은 첫 중첩과 아군 공격에 의한 기절 조건을 설명했는데도 실패로 판정됐습니다. 질문하지 않은 추가 피해 설명이 없다는 것이 이유였습니다. 답변 오류와 채점 오류를 구분하고 질문에서 요구한 조건을 충족했는지 별도로 검토했습니다.

자동 실패 기록을 지우거나 통과할 때까지 답변을 다시 생성하지 않았습니다. 원래의 판정과 검토 결과를 각각 남겨 점수가 달라진 이유를 추적할 수 있도록 했습니다.

결과와 해석

51/90 → 80/90

동일한 30개 질문을 개선 전후 각각 3회씩 실행했을 때의 자동 통과 응답 수입니다.

저장된 2026년 9월 8일 평가 보고서를 기준으로 정리했습니다. 검색 회귀 테스트 1,833개도 통과했지만 검색 회귀와 실제 답변 평가는 서로 다른 검사이므로 결과를 나눠 기록했습니다.

근거 기록: reports/live-quality-213/final.md. 이 수치는 정해진 질문 표본과 보유 자료에 대한 결과이며 전체 서비스 정확도나 실제 사용자 만족도를 뜻하지 않습니다. 리뷰 기능용 지식베이스 구축 및 평가 사례로 소개합니다.

달라진 개발 방식

AI가 오답을 내면 프롬프트부터 바꾸기보다 원천 자료와 검색 경로 그리고 평가 기준을 나눠 확인합니다. 통과율이 올랐다는 사실만으로 개선을 판단하지 않고 어떤 실패를 해결했는지 설명할 수 있는 기록을 남깁니다.

기업 문서를 다루는 AI에서도 답변과 근거가 연결되는지 확인하는 일이 필요합니다. 이 프로젝트에서 쌓은 검색 경로 분석과 평가 경험을 그 과정에 활용하고 싶습니다.
